Everything you need for autonomous AI

A complete local infrastructure for dispatching, monitoring, and managing AI agents.

🎯

Multi-Channel Input

Submit tasks via web dashboard, Telegram bot, CLI command, file drop, or scheduled cron expressions. All channels converge to the same queue.

🔄

Auto-Resume & Checkpoints

Every Claude session is checkpointed. If interrupted (power loss, crash, timeout), tasks resume from exactly where they stopped — no lost context.

📡

Live Streaming

Watch Claude think in real-time via Server-Sent Events. See tool calls, reasoning, and file edits as they happen in the dashboard.

🛡️

Crash Recovery

Orphan detection sweeps find stuck tasks, recovers them to failed/, and marks them resumable. The watcher runs every 60 seconds.

⏱️

Scheduled Tasks

Add cron expressions to task frontmatter and the scheduler fires them automatically. Run code reviews every morning, deploy checks hourly.

🔒

Race-Free Dispatch

flock-based mutex prevents duplicate execution. Multiple watcher triggers can fire simultaneously without ever running a task twice.

Up and running in 2 minutes

Works on any Mac with Claude Code CLI installed.

1

Prerequisites

Ensure you have Claude Code CLI, jq, and optionally watchman installed.

# Install Claude Code (if not already) npm install -g @anthropic-ai/claude-code # Install jq (JSON processor) brew install jq # Optional: watchman for instant file detection brew install watchman
2

Clone the Pipeline

Clone the repo to your home directory. The pipeline expects to live at ~/.claude-pipeline/.

git clone https://github.com/YOUR_USER/claude-pipeline.git ~/.claude-pipeline cd ~/.claude-pipeline
3

Configure

Edit config.yml to set your model preference, Telegram bot token (optional), and notification settings.

# Copy and edit the config cp config.yml.example config.yml vim config.yml # Key settings: model: sonnet # or opus, haiku timeout: 600 # seconds per task budget: 5.00 # max cost per task max_concurrent: 2 # parallel tasks
4

Install & Start Services

The pipeline CLI handles launchd service management. Services auto-restart on crash.

# Make CLI available system-wide ln -sf ~/.claude-pipeline/bin/pipeline /usr/local/bin/pipeline # Install launchd plists pipeline install # Start all services (watcher, dashboard, telegram bot) pipeline up # Verify everything is running pipeline status
5

Submit Your First Task

You're ready! Submit a task and watch it execute.

# Via CLI pipeline add "Write a Python script that finds duplicate files" # Or open the dashboard open http://localhost:7778 # Watch it work pipeline logs --follow

🐛 Code Tasks

Creates a branch, reads the codebase, makes changes, runs tests, and commits. Use for bug fixes, features, and refactors.

pipeline add -t code "Fix the auth timeout bug in login.py"

🔬 Research Tasks

Searches the web, gathers information, synthesizes findings into actionable reports with sources and recommendations.

pipeline add -t research "Compare React vs Svelte for our use case"

✍️ Writing Tasks

Generates documents, blog posts, documentation, and content. Matches the requested tone and format.

pipeline add -t writing "Write API docs for the /users endpoint"

📋 General Tasks

Catch-all for tasks that don't fit other categories. Claude decides the best approach based on the description.

pipeline add "Analyze our error logs from this week"

Tasks are Markdown files with YAML frontmatter. You can create them manually or let the CLI generate them.

--- type: code priority: 8 # 1-10 (10 = highest) auto: true # Auto-approve tool calls model: sonnet # sonnet | opus | haiku timeout: 600 # Max seconds budget: 5.00 # Max cost (USD) repo: /path/to/project # Working directory branch: fix/auth-bug # Git branch to create schedule: "0 9 * * 1-5" # Optional: cron for recurring source: telegram # Where it came from --- # Fix authentication timeout The login endpoint returns 504 after 30s when the database connection pool is exhausted. ## Requirements - Increase pool size to 20 - Add connection timeout of 5s - Add retry logic with exponential backoff

👁 Watcher

Monitors the queue/ directory using watchman (instant notification) or falls back to 5-second polling. On startup, runs orphan detection to recover crashed tasks. Also drives the scheduler (checks cron expressions every 60s).

bin/watcher.sh

🚀 Dispatcher

The execution engine. Uses flock for mutual exclusion, sorts tasks by priority, moves files through lifecycle directories, and invokes Claude CLI with streaming output. Handles retries, timeouts, and notifications.

bin/dispatcher.sh

🌐 API Server

Python HTTP server on port 7778. Serves the dashboard, exposes REST endpoints for task CRUD, and provides SSE streams for real-time task output. Powers the live view in the dashboard.

bin/api-server.py

📱 Telegram Bot

Long-polls the Telegram Bot API (30s timeout). Creates task files from messages, responds to /status and /help commands. Receives completion notifications from the dispatcher.

bin/telegram-bot.sh

📊 Status Generator

Periodically generates dashboard/status.json with queue counts, cost tracking, and service health. Consumed by the dashboard for stat cards.

bin/generate-status.sh

🏃 Service Manager

launchd integration with KeepAlive, ThrottleInterval for auto-restart. The CLI's up/down/install commands manage all three plists. Services survive reboots.

launchd/*.plist

Execution Flow (What Happens When a Task Runs)

1

Acquire Lock

Dispatcher grabs locks/dispatcher-scan.lock with flock -n. If another instance is already scanning, this one exits immediately.

2

Priority Sort

All queue/*.md files are read, frontmatter parsed for priority (1-10). Highest priority task is selected. On ties, oldest file wins (FIFO).

3

Move & Lock

Task file moves from queue/ → active/. A task-specific lock file is created with the shell PID. State directory is initialized.

4

Invoke Claude

claude --resume $session_id -p "$prompt" --model $model --output-format stream-json — output piped to state/$task/stream-output.jsonl in real time.

5

Complete & Notify

On exit code 0: task → done/. Otherwise: check if resumable, task → failed/. Telegram/macOS notification sent. Lock removed. Cost recorded.

Telegram Integration

Control your pipeline from your phone.

The Telegram bot lets you submit tasks, check status, and receive completion notifications — all from a chat interface. Set up:

1

Create a Bot

Message @BotFather on Telegram and send /newbot. Copy the token.

2

Get Your Chat ID

Message your new bot, then visit https://api.telegram.org/bot<TOKEN>/getUpdates to find your chat_id.

3

Configure

# In config.yml: telegram: enabled: true bot_token: "YOUR_BOT_TOKEN" chat_id: "YOUR_CHAT_ID"

Bot Commands

/task <description> Create a general task (priority 5)
/urgent <description> Create a high-priority task (priority 9)
/code <description> Create a code-type task
/research <description> Create a research task
/status Show queue, active, done, failed counts
/help Show available commands
<plain text> Any text without / becomes a general task

REST API

The API server at http://localhost:7778 exposes these endpoints.

MethodEndpointDescription
GET/api/statusPipeline status (counts, costs, services)
GET/api/tasksList all tasks across all states
GET/api/tasks/:idGet task detail + output
POST/api/tasks/createCreate a new task (JSON body)
POST/api/tasks/:id/stopKill a running task
POST/api/tasks/:id/resumeResume a failed task
POST/api/tasks/:id/retryRetry from scratch
DELETE/api/tasks/:idDelete a task file
GET/api/stream/:idSSE stream of task output (live)

Example: Create a Task via API

curl -X POST http://localhost:7778/api/tasks/create \ -H "Content-Type: application/json" \ -d '{ "description": "Optimize database queries in /app/models/", "type": "code", "priority": 7, "model": "sonnet", "repo": "/Users/me/my-project" }'

Example: Stream Live Output

# Connect to SSE stream curl -N http://localhost:7778/api/stream/003-optimize-queries # JavaScript (in browser) const es = new EventSource('/api/stream/003-optimize-queries'); es.onmessage = (e) => { const data = JSON.parse(e.data); console.log(data.type, data.content); };
