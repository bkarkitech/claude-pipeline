What Is This?

A pipeline that turns plain English into executed results — autonomously, with session persistence and crash recovery.

The Claude Pipeline is a local-first, file-based system that lets you describe tasks in plain English and have Claude Code (Anthropic's AI coding agent) execute them without human intervention. It lives entirely on your machine at ~/.claude-pipeline/, uses macOS native tools (Watchman, launchd) for persistence, and communicates through the filesystem — no servers, no databases, no cloud infrastructure beyond the AI API itself.

You Type

pipeline add "fix the auth timeout bug in skykeep" — plain English, nothing else.

AI Generates

Structured task file with inferred type, repo, priority, branch name, acceptance criteria — all automatic.

Pipeline Executes

Claude reads the codebase, implements the fix, commits to a branch, handles failures, can resume if interrupted.

Key Features v3.0

Seven layers of intelligence working together.

1. Intelligent Task Generator (AI-Powered)

Write tasks in plain English. An AI pre-processor (Claude Haiku, ~$0.005/call) turns your words into structured task files with inferred metadata.

terminal 
$ pipeline add "fix the auth timeout bug, users logged out after 5 mins should be 30"

# AI generates:
type: code         # inferred from "fix"
repo: skykeep  # inferred from context
priority: 8        # bug affecting users = high
branch: fix/auth-timeout-session
budget: 5.00       # code task budget
# Plus full description, context, acceptance criteria...
  • Infers type (code/research/review/writing) from natural language
  • Maps project names to repositories automatically
  • Generates branch names with correct prefixes (fix/, feat/, refactor/)
  • Sets appropriate budgets (research=$2, code=$5, complex=$8)
  • Falls back gracefully to simple mode if AI is unavailable
  • --preview flag lets you review before queuing

2. Session Checkpointing & Resumption

If a task is interrupted (timeout, crash, power loss, API error), it can pick up exactly where it left off — no work lost.

terminal 
# Task times out mid-execution
[ERROR] Task 004 timed out after 25s (resumable, session=e2c583d0...)

# Resume exactly where it stopped
$ pipeline resume 004
✓ Resuming with session e2c583d0... (will be attempt 3)
✓ Task re-queued for resumption

# View checkpoint state
$ pipeline state 004
  Session:   e2c583d0-cff9-40ac-bcd6-9854f3dfdea8
  Attempt:   2
  Budget:    $0.09 used
  Resumable: true
  • Native Claude --resume <session-id> for seamless continuation
  • Git state captured before/after each attempt (branch, commits, diff)
  • Context reconstruction fallback if session is expired/corrupted
  • Budget accumulation across attempts (never over-spend)
  • Max 5 attempts before marking non-resumable
  • Orphan detection on startup (catches killed processes)

3. Autonomous Execution Engine

Tasks execute fully autonomously with concurrency control, atomic locking, timeout enforcement, and desktop notifications.

  • Filesystem watcher (Watchman) for instant task detection
  • Atomic locks (set -o noclobber) prevent double-processing
  • Configurable concurrency limit (default: 2 parallel tasks)
  • Background watchdog enforces timeout per task
  • macOS desktop notifications on completion/failure
  • launchd service keeps the system alive across reboots

4. Task Dependencies

Define execution order with depends_on. Tasks wait in pending until all dependencies complete, then auto-queue.

terminal 
# Task B waits for Task A
$ pipeline add "deploy to staging" --depends-on "run-integration-tests"
✓ Task created: 013-deploy-to-staging.md
  -> Blocked on: run-integration-tests

# View dependency graph
$ pipeline deps
  ◻ 013-deploy-to-staging: Deploy to staging
    └── run-integration-tests  [✓ done]
  • depends_on: task-a, task-b frontmatter (comma-separated)
  • Dispatcher checks all deps are in done/ before processing
  • Blocked tasks auto-queue when dependencies complete
  • pipeline deps shows full dependency graph with status
  • --depends-on flag works with both smart and dumb add modes

5. Scheduled & Recurring Tasks

Run tasks on a cron schedule. The watcher evaluates cron expressions every 60 seconds and queues matching tasks automatically.

terminal 
# Run tests every weekday at 9am
$ pipeline add "run integration tests" --schedule "0 9 * * 1-5" --repo myapp

# List all scheduled tasks
$ pipeline schedule
  ⏱  012-run-integration-tests
      Schedule: 0 9 * * 1-5
      Last run: 2026-05-22 09:00

# Remove a schedule
$ pipeline schedule remove 012
  • Standard 5-field cron: min hour dom month dow
  • Supports *, */N, ranges (1-5), comma lists
  • Creates run copies — original task preserved for next trigger
  • De-duplication: won't re-trigger within the same minute
  • Persistent state tracks last-run times across restarts

6. Multi-Channel Notifications (Telegram, Email, Webhook)

Get notified via macOS, Telegram, email, or any webhook endpoint. Each event type (start, complete, failure, timeout) is tagged.

config.yml

  • Email: System sendmail with event headers
  • Webhook: JSON POST to any URL (Slack, Discord, n8n, etc.)
  • Event filtering: choose which events trigger which channels
  • pipeline notify-test verifies all channels with real delivery

Installation

The pipeline is self-contained at ~/.claude-pipeline/. No package manager needed.

Verify Claude Code is installed and authenticated

claude --version — should return v2.1+ and be able to run claude -p "hello"

Ensure the pipeline directory exists

All source lives at ~/.claude-pipeline/. The directory structure is auto-created. Verify with ls ~/.claude-pipeline/bin/

Add pipeline to your PATH

Symlink the CLI: ln -sf ~/.claude-pipeline/bin/pipeline ~/.local/bin/pipeline
Then verify: pipeline help

Configure your repositories

Edit ~/.claude-pipeline/config.yml and add your repos under the repos: section:

repos:
  my-app: /Users/you/Projects/my-app
  backend: /Users/you/Projects/backend
  docs: /Users/you/Projects/documentation

Start the watcher

pipeline watch — starts the filesystem watcher that auto-processes queued tasks.

(Optional) Enable persistence across reboots

Load the launchd service: launchctl load ~/Library/LaunchAgents/com.bkarki.claude-pipeline.plist
The watcher will now auto-start at login and survive crashes.

How It Works

The complete execution flow from plain English to results.

1

Task Creation (Intelligent)

You run pipeline add "your request in plain English". Claude Haiku analyzes your words and generates a structured .md file with YAML frontmatter (type, repo, priority, model, budget, branch) plus a detailed body with context and acceptance criteria. Takes 2-4 seconds, costs ~$0.005.

2

Detection & Queuing

The task file lands in queue/. Watchman instantly detects it and triggers the dispatcher. A periodic sweep every 30s catches anything missed. Tasks with auto: false go to pending/ instead, waiting for pipeline run.

3

Session Initialization

The dispatcher generates a UUID session ID, captures git state (branch, recent commits, uncommitted changes), writes the initial state file to state/<task>/current.json, and acquires an atomic lock.

4

Claude Execution

Claude Code is invoked with --session-id (enabling resumption), the task body as prompt, CLAUDE.md as system prompt, configured model/effort/budget, and a background watchdog enforcing the timeout. Output is captured as stream-json for cost tracking.

5

Result Handling & Checkpointing

Success: Task moves to done/, notification sent. Failure/Timeout: State file updated with resumable: true, git state re-captured, task moves to failed/ with session ID in frontmatter. Budget used is tracked for accumulation.

6

Resumption (if needed)

Run pipeline resume <task>. The dispatcher validates the saved session, uses --resume <session-id> so Claude has full conversation history, and sends "Continue where you left off." If the session is expired, context reconstruction injects git state + log tail into a fresh session.

Design Principles (for contributors)

Filesystem is the Bus

No databases, no message queues. Files move between directories to represent state transitions. Anyone can inspect state with ls and cat.

Bash-Native

No Python, no Node for infrastructure. Pure bash + standard Unix tools (jq, awk, sed). Easy to debug, extend, and understand.

Graceful Degradation

AI unavailable? Falls back to dumb mode. Watchman not installed? Polls. Session expired? Reconstructs from git. Every feature has a fallback.

Zero Trust in External State

Always validate sessions before resume. Always check PID liveness. Always capture git state. Assume any process can die at any time.

Roadmap

What's built, what's next, and where this is heading.

Level 1: Core Pipeline ✓

File-based queue, dispatcher, watcher, CLI, launchd persistence, macOS notifications, concurrency control, timeout handling, retry mechanism.

Level 2: Session Checkpointing ✓

Session persistence with UUIDs, resume after interruption, git state capture, attempt tracking, budget accumulation, orphan detection, context reconstruction fallback.

Level 3: Intelligent Task Generator ✓

AI-powered task file creation from plain English. Infers type, repo, priority, branch, budget. Preview mode. Graceful fallback to dumb mode.

Level 4: Orchestration & Notifications ✓

Task dependencies with auto-unblocking, scheduled/recurring tasks via cron, multi-channel notifications (Telegram/Email/Webhook), cost reporting with budget alerts, dependency graph visualization.

Level 5: Multi-Agent & Advanced Integrations (Next)

Agent-to-agent communication (one task spawns sub-tasks), priority queue ordering, task chaining (output of one feeds into next), Slack/Discord integration bots.

Level 6: Platform

Mobile task creation (via file sync), multi-machine coordination, plugin system for new task types, approval workflows for sensitive operations, team features.

Double-processingAtomic lock via set -o noclobber; echo $$ > lockfile
Concurrency limitCount files in active/ before processing (default max: 2)
Stale locksAuto-cleaned if PID is dead (checked on startup via orphan detection)
Runaway tasksBackground watchdog kills Claude after configured timeout

Claude Invocation (v2 with Session Persistence)

bash 
# Fresh execution (first attempt):
cd /Users/you/Projects/your-repo
claude -p --verbose \
  --dangerously-skip-permissions \
  --session-id "a1b2c3d4-e5f6-..." \
  --model sonnet \
  --effort max \
  --max-budget-usd 5.00 \
  --output-format stream-json \
  --append-system-prompt-file CLAUDE.md \
  "$TASK_BODY"

# Resume execution (after interruption):
claude --resume "a1b2c3d4-e5f6-..." \
  -p --verbose \
  --dangerously-skip-permissions \
  --model sonnet \
  --max-budget-usd 3.53 \  # remaining budget
  --output-format stream-json \
  "Continue the task from where you left off."
